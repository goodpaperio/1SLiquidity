# V1.0.9 Deployment Runbook

This runbook defines the recommended deployment and post-deployment sequence for `v1.0.9`, including fresh deployment, ETH support wiring, Balancer seeding, and validation gates.

## Scope

- Deploy the full protocol fresh using the orchestrator script.
- Ensure `ETHSupport` is deployed and configured as part of the fresh flow.
- Seed Balancer pools from locally generated and fork-validated candidates.
- Validate protocol behavior with matrix and core test suites.

## Preconditions

- `.env` is configured with:
  - `MAINNET_RPC_URL`
  - deploy account configuration used by Forge (`deployKey`)
  - Etherscan API key if verification is used in your release process
- `v1.0.9` branch is up to date locally.
- Local Balancer source data can be refreshed (`keeper/data/balancer-pools.json`).

## Phase 0 - Refresh Balancer Source Data

1. Refresh Balancer pool data:
   - `cd keeper && npm run balancer:fetch`
2. Return to repo root:
   - `cd ..`
3. Regenerate candidates from local source:
   - `npm run balancer:seed:candidates`
4. Validate candidates on fork:
   - `npm run test:balancer-seed-candidates:anvil`

Gate:
- Do not continue if candidate validation reports failures.

## Phase 1 - Fresh Protocol Deployment

Run the full fresh deployment:

- `npm run deploy:fresh:protocol`

Expected outcome:
- Core protocol components are deployed in one run, including:
  - fetchers,
  - `Registry`,
  - `Executor`,
  - `Create2Factory`,
  - `StreamDaemon`,
  - `Core`,
  - `ETHSupport`.

Exported artifact:
- `deployments/protocol-fresh-mainnet.env`

## Phase 2 - Address Artifacts and Sync

1. Extract versioned addresses:
   - `npm run extract:addresses:v1.0.9`
2. Sync Solidity address library:
   - `npm run sync:mainnet-addresses:sol`

Gate:
- Verify extracted addresses match expected contracts from the fresh deployment output.

## Phase 3 - Seed Balancer Pools (Validated Candidates)

Use the validated candidate file:
- default file: `docs/balancer-seed-candidates.json`

Run full seeding:
- `BALANCER_REGISTRY_ADDRESS=<registry_address> npm run deploy:seed:balancer:validated`

Recommended batched seeding:
- `BALANCER_REGISTRY_ADDRESS=<registry_address> BALANCER_SEED_START=0 BALANCER_SEED_END=20 npm run deploy:seed:balancer:validated`
- `BALANCER_REGISTRY_ADDRESS=<registry_address> BALANCER_SEED_START=20 BALANCER_SEED_END=40 npm run deploy:seed:balancer:validated`
- `BALANCER_REGISTRY_ADDRESS=<registry_address> BALANCER_SEED_START=40 BALANCER_SEED_END=9999 npm run deploy:seed:balancer:validated`

Notes:
- Script is idempotent for already-seeded pools (it skips existing pool entries).
- Use conservative batch sizes if gas conditions are volatile.

## Phase 4 - Validation After Deployment and Seeding

1. Run mixed matrix (core + balancer):
   - `npm run test:quote-matrix:anvil:reserve`
2. Optional diagnostics:
   - core-only baseline: `npm run test:quote-matrix:anvil:core`
   - balancer-only behavior: `npm run test:quote-matrix:anvil:balancer-only`
3. Run full protocol regression suite:
   - `npm run test:all:anvil`

Gate:
- No unexpected regressions in core test suite.
- Matrix failure profile should be unchanged or improved relative to baseline.

## Operational Notes

- Price-based matrix remains non-gating when excessive debug output risks out-of-gas.
- Candidate generation is intentionally conservative (validated pools only).
- Re-run Phase 0 whenever Balancer data is refreshed to keep candidates current.

## Future Update Workflow

For future releases:
1. Run fresh deployment (`deploy:fresh:protocol`).
2. Seed Balancer with validated candidates (`deploy:seed:balancer:validated`).
3. Re-run matrix + full tests.
4. Promote new address artifacts and deployment notes.
